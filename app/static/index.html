TFM GNSS pipeline - local interface

Each section runs one pipeline step by reusing the exact same functions as its console script - results are saved to the same place as always (results/<station>/<year>/...). Step 0 runs first and builds the Parquet files every other step reads. Steps 1-6 are connected, each with its cross-station comparator (X.2) where one exists. The Ndat criterion in the bar above applies to Steps 2-6; Step 1 completeness is independent of Ndat.

00

Step 0 - Input data preparation

No prerequisite Not run

Converts the daily RAW files into one Parquet file per station under results/<station>/<year>/0_parquet/ - the form every other step reads. It performs no scientific analysis: nothing is filtered or removed, and the QC flag columns it writes are informational only. Every configured station is always processed in a single pass, because each daily RAW file already mixes all stations together.

The folder holding the daily RAW files (rotiS4.2024001 ... rotiS4.2024366). Relative paths resolve against the folder the server was started from, same convention as results/; an absolute path (D:\data\datos_2024) also works.

Step 1 - Completeness

Requires Step 0 Not run

Completeness measures temporal data availability, not scientific quality: a day is "valid" if at least the coverage threshold (75% by default) of its 1440 minutes has some observation recorded - it says nothing about whether those ROTI values themselves are reliable (that is a separate quality control step, not applied to any result yet). DoY = day of year (1-366).

Requires Step 1 Not run

2A. Monthly percentile analysis

Purpose: Step 2 characterizes the monthly distribution and variability of ROTI L1 using only the days classified as valid in Step 1. Monthly p90 and p99 describe the upper part of the ROTI L1 distribution and allow its seasonal variability to be compared across the year.

Requires Step 1 to already exist for that station (Step 2 reads its coverage CSV).

2B. Monthly CCDF analysis

Purpose: The CCDF shows the probability of observing ROTI L1 values equal to or greater than a given value. It provides the full upper-tail distribution behind the monthly percentiles instead of reducing each month to only p90 and p99.

How to read

  • CCDF = 0.1 corresponds approximately to p90.
  • CCDF = 0.01 corresponds approximately to p99.
  • The Y axis is logarithmic.
  • n in the legend is the number of ROTI L1 observations used for that curve.
  • Within-station comparison overlays selected months from the same station.

Step 3 - Daily variability

Requires Step 1 Not run

Requires Step 1 to already exist for that station (Step 3 reads its coverage CSV). Annual p90/p99 thresholds are computed once from all valid days in the year; daily frequency then measures what share of each day's own observations exceed those fixed annual thresholds - it is not a per-day percentile.

Station Year n_values p90 annual [TECU/min] p99 annual [TECU/min] Frequency >=p90 [%] Frequency >=p99 [%]

Cross-station daily comparison

Compares whichever stations already have Step 3 output for the Year/DoY range set above - reads what Step 3 already saved, does not recompute anything. Shows each station's annual thresholds, its day of maximum p90/p99 exceedance frequency, and which dates show up in the top-N days of 2 or more stations at once. A shared date means both stations were elevated relative to their own annual threshold - not that they had the same absolute ROTI L1 value that day.

Step 4 - Hourly variability (local hour)

Requires Steps 1 & 3 Not run

Requires Step 1 (coverage) AND Step 3 (annual thresholds) to already exist for that station - Step 4 reads both. Frequency is measured by local hour (each station's own fixed UTC offset, CLAUDE.md §6), against the same annual p90/p99 thresholds Step 3 already computed - not a new percentile per hour.

Station Year Max p90 hour(s) Max p90 freq [%] Support Max p99 hour(s) Max p99 freq [%] Support

Cross-station hourly comparison

Compares whichever stations already have Step 4 output for the Year/DoY range set above - reads what 4.2-hourly_comparison.py already saved, does not recompute anything. Each station uses its own annual p90/p99 threshold, so this compares relative exceedance frequency by local hour between stations, not absolute ROTI L1 magnitude.

Reading note: local hour is cyclic - 23h and 00h are consecutive, not the two ends of a line. A station elevated at both edges of the 0-23 axis may reflect one continuous nocturnal structure, not two separate peaks.

Step 6 - Month-hour heatmaps

Requires Steps 1 & 3 Not run

Requires Step 1 (coverage) AND Step 3 (annual thresholds) to already exist for that station - Step 6 reads both. Frequency is measured on a full 12 (month) × 24 (local hour) grid against the same annual p90/p99 thresholds Step 3 already computed. The Top-10 tables below list the single highest-frequency month-hour cells - a reproducible result. Grouping adjacent cells into ranges (e.g. "22h-01h") is still a manual step, not done by this page.

Color scales are adjusted independently for each station. Compare the numerical frequencies/colorbars, not color intensity alone, across stations.
